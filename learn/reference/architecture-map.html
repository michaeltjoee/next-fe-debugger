The one pipeline every tab goes through

page (MAIN world)                         extension page (popup or panel)
───────────────────                       ──────────────────────────────────────────────
readPage()  ── runs in page ──►  NextDataResult (plain JSON)
  src/shared/read-next-data.ts            │
  serialized with .toString()             ▼
                                     renderBody(out, result, activeTab, {filter, raw})
  panel: inspectedWindow.eval(             src/shared/inspector.ts
    `(${readPage.toString()})()`)      ├─ version   → renderVersion
  popup: scripting.executeScript({         ├─ gateway   → renderGateway    ┐
    func: readPage, world: "MAIN"})    ├─ page      → renderPageData   ├→ renderTree (json-tree.ts)
                                           └─ datalayer → renderDataLayer  ┘

Rule: readPage, gatewayStamp, dataLayerStamp and clearDataLayer are sent to the page as source text, so they can't use imports or anything outside their own body. Their result must be JSON (hence the JSON.parse(JSON.stringify(…)) round trips).

Version tab

  1. In the page: collect every script[src], link[href] and performance resource URL.
  2. Regex <origin>/<service>/<vX.Y.Z>/_next/ groups them into AssetBundles; …/shared-components/… go to shared.
  3. primaryBundle: the bundle matching __NEXT_DATA__.assetPrefix, else the one with most files.
  4. renderVersion: headline (click to copy), counts, collapsed file groups.
read-next-data.ts:77-97 · inspector.ts:47-51, 112-210

API Fetch tab: recording

  1. gateway-hook.ts runs in MAIN at document_start, before page scripts.
  2. Replaces window.fetch and XMLHttpRequest.prototype.open/setRequestHeader/send with wrappers that call the originals.
  3. Only URLs containing /ms-gateway/ (minus IGNORED_PATHS) are logged: request on start, status/headers/body (cloned) on finish.
  4. Log = non-enumerable window.__MS_GATEWAY__ {session, version, calls}; max 300 calls, bodies > 1 MB summarised; version++ on every change.
gateway-hook.ts · global.d.ts:33-63

API Fetch tab: reading

  1. readGateway copies the hook's calls.
  2. Adds performance resource entries (fetch/xmlhttprequest, /ms-gateway/) the hook didn't record, as unrecorded (no method or bodies).
  3. Counts ignored paths instead of listing them; sorts by startedAt.
  4. renderGateway: one row per call, filter on URL then bodies/headers, rows reused across re-renders so open rows stay open.

Page Data tab

  2. window.__CORE_DATA__ via JSON round trip (error kept if it can't serialize).
  3. App Router detection: no data and self.__next_f is an array.
  4. renderPageData: one folding section per global, pinned head, tree with rootPath so key clicks copy __NEXT_DATA__.props….

dataLayer tab

  1. readDataLayer slices window.dataLayer from __clearedAt.
  2. toJson replacer: DOM nodes → [button#push], functions/cycles labelled, gtag's arguments → array.
  3. describePush + eventOf group by event; gtag("event", x) joins {event: x}; gtm.* drawn lighter.
  4. New pushes since the last render get the fresh class (yellow fade).

Gotchas worth remembering

  • Content scripts can't be ES modules, so content.ts and gateway-hook.ts import nothing; shared types are ambient in src/global.d.ts (an import type would make tsc emit export {}).
  • IGNORED_PATHS lives in two files (gateway-hook.ts and readGateway) because neither can import. Keep them in sync.
  • Build before load: manifest points into dist/. npm run build = tsc + scripts/copy-static.js.
  • __NEXT_DATA__ reflects the first server render; client-side route changes don't update it.
  • Server-side (SSR) gateway calls are invisible; the hook only sees the browser.
  • Pages open before the extension loaded have no hook, so API Fetch falls back to resource timing only (recording: false).
